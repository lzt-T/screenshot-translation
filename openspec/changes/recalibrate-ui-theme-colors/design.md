## Context

当前渲染层通过 `main.css` 中的 CSS 变量向 Tailwind v4 暴露语义颜色，主窗口、通用组件、截图选区和结果浮层均消费这些 token。现有结构已经实现浅色、深色与跟随系统主题，不需要改变主题机制或组件 API。

## Goals / Non-Goals

**Goals:**

- 通过集中调整语义 token 完成颜色校准，避免在页面组件中散布具体色值。
- 使用不带明显青绿色倾向的石墨中性色建立表面层级。
- 使用单一矿物蓝连接主操作、选择、焦点与跨窗口反馈。
- 在浅色和深色主题中维持足够的文字、控件与焦点对比度。

**Non-Goals:**

- 不调整布局、字体、圆角、阴影结构、组件尺寸或动效。
- 不修改导航、文案、路由、表单字段或业务行为。
- 不新增主题、调色板选择器或第三方依赖。

## Decisions

### 使用现有语义 token 作为唯一修改入口

保留 `background`、`card`、`sidebar`、`primary`、`accent`、`ring` 与浮层 token 的现有接口，只替换变量值。这样所有通用组件和窗口会自动获得一致配色，修改范围最小。

替代方案是在各页面逐个覆盖颜色类。该方案容易产生局部漂移，也会增加后续维护成本，因此不采用。

### 采用石墨灰与矿物蓝单强调体系

核心颜色基线如下，派生 token 应保持同一中性色温和同一强调色色相：

| 语义角色 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 页面背景 | `#F6F7F9` | `#15181C` |
| 卡片 | `#FFFFFF` | `#1E2329` |
| 侧栏 | `#F0F2F5` | `#191D22` |
| 主文字 | `#182026` | `#F0F3F5` |
| 次要文字 | `#66717A` | `#A8B0B8` |
| 边框 | `#DDE2E7` | `#343B44` |
| 主强调 | `#335FD1` | `#7D9FF2` |
| 淡强调 | `#E9EEF9` | `#29344D` |

浅色主题主按钮使用矿物蓝背景与浅色文字。深色主题使用提亮后的矿物蓝与深色文字，以保持按钮内容清晰。错误色继续保持独立红色语义。

替代方案包括朱砂红和翡翠绿。朱砂红在高频工具中攻击性较强，翡翠绿与现有青灰体系距离过近，因此选择矿物蓝。

### 保持跨窗口语义连续

截图选区边界与结果浮层交互状态继续使用 `floating-accent`，其色相与主主题的矿物蓝一致，但可针对透明背景提高亮度。遮罩和浮层表面维持中性深色，不继承主窗口明亮表面。

### 仅在语义必要时使用强调色

实色矿物蓝仅用于主按钮、已激活控件、焦点环和需要即时辨识的状态。侧栏当前项、悬停、徽标和内容提示使用淡强调背景或中性色，不扩大实色强调面积。

## Risks / Trade-offs

- [风险] 深色主题的提亮矿物蓝可能在大面积使用时过亮。 -> 仅允许主操作与小面积状态使用实色主色。
- [风险] 透明浮层叠加不同屏幕内容后对比度不稳定。 -> 为选区和浮层保留独立的高亮 `floating-accent`，不直接复用不透明按钮色值。
- [风险] 个别组件可能存在局部颜色覆盖，导致 token 更新后视觉不一致。 -> 实施时只检查现有语义颜色消费点，删除由本次调整产生的冲突覆盖，不进行无关重构。

## Migration Plan

1. 更新浅色与深色主题的语义颜色变量。
2. 同步更新侧栏、图表和浮层的同类派生颜色。
3. 检查主窗口各核心页面以及截图选区、结果浮层的视觉语义。
4. 如出现明显可读性或状态辨识问题，回滚 `main.css` 的主题 token 变更即可恢复原配色。
