## Context

当前渲染层已经使用 Tailwind v4、CSS 变量、`next-themes`、Radix 原语和项目内 UI 组件，浅色与深色主题集中定义在 `main.css`。应用包含固定侧栏、五个主页面，以及独立的截图选区和翻译结果窗口。

现有视觉语言将靛紫主色同时用于主操作、焦点、选中、状态、图标和装饰，并在页面中重复使用 `lab-panel`、测量标签和分隔行。视觉重建需要跨越应用外壳、共享组件和多个页面，但不得改变业务 Hook、IPC、路由或数据结构。参见 `proposal.md` 和 `specs/calm-workbench-interface/spec.md`。

## Goals / Non-Goals

**Goals:**

- 建立可由所有渲染窗口复用的语义主题 token，而不是在页面中散布固定颜色。
- 让主要任务获得明确视觉优先级，降低辅助状态、装饰标签和容器边界的噪音。
- 用少量可复用布局规则统一页面，同时允许翻译、对话、收藏和设置保留各自的信息结构。
- 以手术性修改完成重建，复用现有组件和依赖，并保持现有用户工作流。

**Non-Goals:**

- 不修改导航结构、业务文案含义、翻译流程、模型配置流程或学习数据模型。
- 不重构主进程、IPC、数据库、服务或业务 Hook。
- 不引入新的组件库、图标库、动画库或状态管理方案。
- 不增加展示型动效、玻璃拟态、渐变文字、品牌插画或神兽视觉元素。

## Decisions

### 1. 通过现有 CSS 变量重建语义主题

在 `main.css` 中保留现有 Tailwind 语义映射，替换底层浅色与深色 token。浅色主题使用冷灰白背景、近白内容面、深石墨正文和青石蓝强调；深色主题使用蓝调石墨背景、分级深色表面、浅灰正文和较亮青色强调。

主色建议以浅色 `#2F6F78`、深色 `#72B8BE` 为校准起点，最终以正文、按钮和焦点环的实际对比度检查为准。错误色作为独立语义色保留。成功、处理中和普通信息默认通过文字、图标和中性表面区分，不自动占用品牌实色。

选择该方案是因为项目已有完整的语义 token 管线，可在不替换组件库的情况下同步全部页面。替代方案是逐组件使用 Tailwind 固定颜色，但会增加双主题漂移和跨窗口不一致风险。

### 2. 保留三种主题模式和统一主题入口

继续由现有主题提供器负责 `system`、`light` 和 `dark`。主题只在应用根级切换，页面与区块不得自行反转主题。设置页将三张大型主题卡简化为紧凑选择控件，但保留现有持久化键和行为。

替代方案是只提供单一主题，以减少设计成本；该方案会移除现有能力并降低桌面环境适应性，因此不采用。

### 3. 应用外壳采用紧凑侧栏和页面工具栏

侧栏目标宽度调整到 192-200px，品牌区降低视觉重量。活动导航使用背景、文字和图标的一致状态，不再叠加装饰圆点。页面标题从展示型 36px 调整为桌面产品常用的 24-28px，并与主要页面操作处于同一紧凑工具栏。

Smiley Sans 仅保留给品牌字标；页面标题与正文使用现有系统字体栈，快捷键和确有测量含义的内容继续使用等宽字体。

替代方案是改为纯图标窄轨侧栏，但五个导航入口包含相近概念，仅用图标会降低可识别性，因此保留文字标签。

### 4. 首页使用一个连续双栏工作面

首页保留原文约 42%、译文约 58% 的桌面比例，但将两个独立 `lab-panel` 合并为一个拥有内部工具栏和中央分隔的工作面。原文操作归入原文工具栏，结果操作归入译文工具栏，底部快捷键和翻译操作保持在输入侧的稳定位置。

在空间不足时切换为上下布局，并让每个区域具有独立的合理最小高度，不依赖固定视口高度强撑页面。加载、错误、空状态和翻译结果只替换译文区域内容，避免整个页面跳动。

替代方案是继续保留两张卡片，仅调整颜色。该方案无法解决面板割裂和同等权重问题，因此不采用。

### 5. 各页面共享表面规则，不共享僵硬模板

共享规则包括：一个页面工具栏、一个主要内容工作面、必要时使用内部区域分隔、普通内容无阴影、统一 8px 控件圆角与 10px 表面圆角。

- 口语对话保持控制区与记录区的双区结构，但视觉上属于同一会话工作面。
- 学习收藏将搜索和筛选作为列表工具栏，列表与详情使用连续层级。
- 设置页使用分组偏好行和模型配置展开区，避免额外卡片嵌套。
- 关于页取消大面积反色品牌卡，使用与应用一致的内容面和简洁操作列表。

不提取覆盖所有页面的通用页面组件。现阶段页面数量有限，强行抽象会隐藏各页面结构差异；只复用确有重复语义的基础组件和 CSS token。

### 6. 动效只表达反馈和状态变化

控件悬停、按下、展开和内容替换使用约 120-180ms 的透明度、颜色或轻微位移过渡。删除无必要的页面进入动画和持续装饰动画。所有非必要动画继续受 `prefers-reduced-motion` 约束。

不新增 Motion 或 GSAP。现有 CSS 能覆盖本次所需反馈，引入动画依赖会增加复杂度且不符合高频桌面工具定位。

### 7. 临时窗口共享颜色语义但保留专用材质

截图选区和结果浮层继续使用透明窗口专用遮罩与浮层 token，但其强调色、文字层级、边界和焦点反馈从主主题派生。浮层不直接套用主窗口白色内容面，以免破坏屏幕内容上的可读性。

## Risks / Trade-offs

- [青石蓝在不同显示器上可能偏灰，主按钮识别度不足] → 使用实际浅色和深色背景检查对比度，并只在主操作上使用实色以提高相对突出度。
- [合并首页工作面可能影响窄窗口布局] → 明确桌面双栏和窄窗口上下布局边界，避免依赖固定宽度和不可收缩内容。
- [减少卡片和边框后页面分组可能变弱] → 通过间距、背景层级、工具栏位置和必要分隔建立层级，不一次性删除所有结构线。
- [跨页面同时重建容易造成中间状态不一致] → 按 token、基础组件、应用外壳、核心页面、临时窗口的顺序实施，每个阶段保持可回退。
- [Smiley Sans 使用减少会削弱原有品牌识别] → 在侧栏品牌字标保留字体，同时通过稳定的青石蓝和更克制的品牌图形建立新识别。

## Migration Plan

1. 更新主题 token、字体使用规则和基础表面样式，同时保持现有类名兼容。
2. 调整共享按钮、输入、选择、徽标和主题选择控件的状态层级。
3. 重建应用外壳和首页连续翻译工作面。
4. 依次迁移口语对话、学习收藏、设置和关于页面。
5. 同步截图选区与结果浮层的专用主题 token。
6. 在浅色、深色和跟随系统模式下进行视觉检查，并检查常用窗口宽度、键盘焦点和减少动态效果。

若需要回退，可按实施阶段恢复对应渲染层文件；此次变更不包含数据迁移、API 迁移或不可逆状态变化。
